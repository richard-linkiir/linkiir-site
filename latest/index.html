Upgrade procedure

In-place, one node at a time.

Grid upgrades are rolling on an HA topology. Queues drain, in-flight messages are durable, and a node that comes back on the new version rejoins on its own.

Read the upgrade notes

Check the release notes for anything marked breaking or action required between your version and this one. Skipping a major means reading each set in order.

Back up config and the archive database

grid backup --out ./pre-upgrade. Takes minutes, and it is the difference between a bad afternoon and a bad week.

Upgrade the standby node first

Let it rejoin, confirm it is healthy in the console and taking traffic, then move to the primary. On a single-node deployment, expect a short window while the runtime restarts. Queued messages are not lost.

Verify, then replay if you need to

Check System Status shows all services online, watch throughput return to normal, and replay anything that dead-lettered during the window.

    Something looks wrong?

    Raise it in Jira Service Management and an engineer will pick it up. Rolling back is grid upgrade --package <previous> plus the backup you took in step two. Don't push through a failed upgrade at 3 a.m.; call us.
